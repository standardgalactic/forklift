# Metric semantics

Commit count is the number of commits reachable from the selected revision excluding those reachable from the optional base. Each commit is compared to its first parent, or the empty tree for a root. This is not a measure of independent work; merge diffs can recount changes. Snapshot bytes sum logical blob sizes at the selected tree, not packed storage. Gitlinks have no byte size. Contributors are primary author name/email pairs after Git mailmap processing. Text churn is Git numstat additions and deletions; binary counts are unknown, not zero textual edits. Optional rename detection uses Git similarity and records both endpoints; it does not infer persistent identity. Architectural categories are ordered glob rules, first match wins. Incidence counts commits touching a category; exclusive footprints count exact category sets. Directional coupling is joint incidence divided by source incidence; Jaccard divides by union incidence; lift divides observed joint incidence by the independence expectation. None establishes causal coupling or labour cost.

### File co-occurrence (v0.6)
Each commit contributes at most one count per destination path and unordered pair. The displayed network selects the top 100 paths by incidence (lexical tie-break), then up to 200 edges by co-occurrence (lexical tie-break). Jaccard uses full selected-path incidence. The graph is a truncated historical association, not evidence of dependency or causality. Rename records retain commit and both paths, without resolving branching or path reuse.
